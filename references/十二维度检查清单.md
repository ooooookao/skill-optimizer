# 十二维度检查清单

> 何时读：分析 skill 时逐项检查。

---

## 1. 模块化分层

- [ ] SKILL.md ≤ 200 行？
- [ ] 详细操作在 steps/ 目录？
- [ ] 参考资料在 references/ 目录？
- [ ] 模板在 assets/templates/ 目录？
- [ ] 不是每次都需要的内容不在 SKILL.md 里？

**常见问题：** SKILL.md 塞了太多细节，应该拆到 step 文件。

---

## 2. 内联 checklist

- [ ] 每个 step 文件顶部有 ✓ 执行清单？
- [ ] 清单标记了最低要求？
- [ ] 工作流导航中每步有 ✓ 标记？
- [ ] 关键节点有 ⚠️ 强制拦截（Gate）？（用户确认点/并行汇聚点/质量检查点/循环入口）

**常见问题：** step 文件没有清单，agent 容易跳步。没有 Gate 的 skill 会在用户确认、并行任务汇聚等节点被 agent 跳过。

---

## 3. 熔断机制

- [ ] 子 agent 调用失败有重试+降级路径？
- [ ] 质量不达标有熔断机制（3次→暂停→报告）？
- [ ] 熔断时给用户提供了选项？
- [ ] 每次子 agent 返回后有 ⚠️ 验证 Gate？（检查成功/输出完整/格式正确）

**常见问题：** 没有熔断，agent 无限重试。子 agent 返回后没有验证，错误输出直接流入下一步。

---

## 4. 确认前置

- [ ] 生成结果后先展示给用户确认？
- [ ] 确认后再做质量检查？
- [ ] 不是"检查完才给用户看"？

**常见问题：** 先评分再展示，用户看到低分先入为主。

---

## 5. 语义边界触发

- [ ] 触发条件基于业务语义？
- [ ] 不是"每 N 次"的机械计数？
- [ ] 有兜底机制防止失控？

**常见问题：** 触发条件太宽泛或太机械。

---

## 6. 多维审查

- [ ] 评分覆盖"质量"层面？
- [ ] 评分覆盖"风险"层面？
- [ ] 有扣分项（底线检查）？
- [ ] 阈值经过实际验证？

**常见问题：** 只检查质量，不检查风险（如提示词过长）。

---

## 7. 用户选择

- [ ] 策略性决策交给了用户？
- [ ] agent 只提供选项和利弊？
- [ ] 不替用户做判断？

**常见问题：** agent 自动选择策略，用户没有参与感。

---

## 8. Token 效率

- [ ] 参考资料是速查表格式？
- [ ] 没有跨文件重复内容？
- [ ] SKILL.md 只放每次都需要的内容？
- [ ] 示例精简（一个高质量 > 三个平庸）？
- [ ] 复杂 skill（≥5步/并行任务）是否用子 agent 隔离上下文？

**常见问题：** 参考资料写成长篇教程，SKILL.md 塞了不常用的内容。复杂 skill 全部在主 agent 里跑，上下文膨胀导致后期输出质量下降。

---

## 9. 交付格式

- [ ] 输出格式清晰易读？
- [ ] JSON 合法？
- [ ] 有设计说明？
- [ ] 错误信息清晰（告诉用户出了什么问题）？

**常见问题：** 只输出 JSON 没有说明，错误信息不可读。

---

## 10. 工作区权限

- [ ] 有权限配置流程？
- [ ] 确认工作区后询问用户是否自动配置权限？
- [ ] 权限配置写入 settings.json（合并，不覆盖）？
- [ ] 敏感操作有二次确认？

**常见问题：** 没有权限配置，用户反复点击确认弹窗。权限配置写成覆盖而非合并。

---

## 11. README

- [ ] 有 README.md？（结构检查）
- [ ] README 描述与实际项目同步？（LLM 内容检查：功能、工作流、文件结构、触发条件是否一致）

**常见问题：** README 是早期写的，项目改了但 README 没更新。

---

## 12. 经验积累

- [ ] 有经验积累机制？（越用越聪明：经验库/知识库/历史记录/反馈循环）
- [ ] 经验格式是结构化的（表格/JSON）？

**常见问题：** Skill 每次运行都从零开始，不积累经验。经验用自由文本存储，无法检索。
