# 九原则检查清单

> 何时读：分析 skill 时逐项检查。

---

## 1. 模块化分层

- [ ] SKILL.md ≤ 200 行？
- [ ] 详细操作在 steps/ 目录？
- [ ] 参考资料在 references/ 目录？
- [ ] 模板在 assets/templates/ 目录？
- [ ] 不是每次都需要的内容不在 SKILL.md 里？

**常见问题：** SKILL.md 塞了太多细节，应该拆到 step 文件。

---

## 2. 内联 checklist

- [ ] 每个 step 文件顶部有 ✓ 执行清单？
- [ ] 清单标记了最低要求？
- [ ] 工作流导航中每步有 ✓ 标记？

**常见问题：** step 文件没有清单，agent 容易跳步。

---

## 3. 熔断机制

- [ ] 子 agent 调用失败有重试+降级路径？
- [ ] 质量不达标有熔断机制（3次→暂停→报告）？
- [ ] 熔断时给用户提供了选项？

**常见问题：** 没有熔断，agent 无限重试。

---

## 4. 审查前置

- [ ] 生成结果后先展示给用户确认？
- [ ] 确认后再做质量检查？
- [ ] 不是"检查完才给用户看"？

**常见问题：** 先评分再展示，用户看到低分先入为主。

---

## 5. 语义边界触发

- [ ] 触发条件基于业务语义？
- [ ] 不是"每 N 次"的机械计数？
- [ ] 有兜底机制防止失控？

**常见问题：** 触发条件太宽泛或太机械。

---

## 6. 多维审查

- [ ] 评分覆盖"质量"层面？
- [ ] 评分覆盖"风险"层面？
- [ ] 有扣分项（底线检查）？
- [ ] 阈值经过实际验证？

**常见问题：** 只检查质量，不检查风险（如提示词过长）。

---

## 7. 用户选择

- [ ] 策略性决策交给了用户？
- [ ] agent 只提供选项和利弊？
- [ ] 不替用户做判断？
- [ ] 确认工作区后询问用户是否自动配置权限？
- [ ] 权限配置写入 settings.json（合并，不覆盖）？

**常见问题：** agent 自动选择策略，用户没有参与感。缺少工作区权限配置，用户反复点击确认弹窗。

---

## 8. Token 效率

- [ ] 参考资料是速查表格式？
- [ ] 没有跨文件重复内容？
- [ ] SKILL.md 只放每次都需要的内容？
- [ ] 示例精简（一个高质量 > 三个平庸）？

**常见问题：** 参考资料写成长篇教程，SKILL.md 塞了不常用的内容。

---

## 9. 交付格式

- [ ] 输出格式清晰易读？
- [ ] JSON 合法？
- [ ] 有设计说明？
- [ ] 错误信息清晰（告诉用户出了什么问题）？
- [ ] 有 README.md？（结构检查）
- [ ] README 描述与实际项目同步？（LLM 内容检查：功能、工作流、文件结构、触发条件是否一致）

**常见问题：** 只输出 JSON 没有说明，错误信息不可读。README 是早期写的，项目改了但 README 没更新。
