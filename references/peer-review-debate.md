# 同行评审辩论模板

> 何时读：需要对 skill 或修改方案做深度审查时。启动 2 个子 agent 正反辩论。

---

## 使用场景

| 场景 | 辩论焦点 | 时机 |
|---|---|---|
| 方案评审 | 修改方案是否合理、有没有遗漏或过度修改 | Step 2 用户确认后 |
| 最终审查 | 修改后的 skill 是否可以交付、有没有遗留问题 | Step 3 评分后 |

---

## 正方 Prompt 模板

```
你是正方辩手。你的立场是：[目标 skill / 修改方案] 可以 [定稿 / 执行]。

请读取以下全部文件，逐文件审查：
[列出所有相关文件路径]

然后从以下角度论证，用中文输出，1500字以内：

1. **架构完整性**：工作流是否完整覆盖了核心功能的全生命周期？
2. **评分体系**：权重分配、检查维度、门禁条件是否合理且自洽？
3. **工具链完整度**：脚本/模板/参考资料是否覆盖了所有需要自动化的环节？
4. **内容质量**：step 文件的操作指南是否清晰可执行？reference 文件是否速查表格式？
5. **跨文件一致性**：术语、分数、门禁条件、文件引用是否全部一致？
6. **可测试性**：evals 是否覆盖了主要场景和边界？

每个论点都要引用具体文件和行号作为证据。如果发现任何小问题，也要指出来（但论证"小问题不影响定稿"）。
```

## 反方 Prompt 模板

```
你是反方辩手。你的立场是：[目标 skill / 修改方案] 还有问题，不能 [定稿 / 执行]。

请读取以下全部文件，逐文件审查：
[列出所有相关文件路径]

然后从以下角度找出残留问题，用中文输出，1500字以内：

1. **跨文件一致性**：逐文件检查术语、分数、门禁条件、文件引用是否全部一致。
   特别注意：文档描述 vs 脚本实际行为是否一致。
2. **脚本逻辑问题**：扣分幅度是否合理？门禁逻辑是否正确？自动修复是否覆盖了文档描述的场景？
3. **内容完整性**：step 文件是否有遗漏的操作？prompt 模板是否有遗漏？evals 是否缺关键场景？
4. **设计一致性**：检查清单的 section 是否与定义的维度完全对齐？有没有跨文件重复？
5. **竞品对比**：使用 find-skills 搜索同类 skill，对比被评估 skill 与同类 skill 的差异，找出可借鉴之处和不足。

每个问题都要引用具体文件和行号。只报告真正需要修的问题，不要报告"可以接受"的小瑕疵。
```

---

## 辩论流程

```
启动正方 agent（background=true）
启动反方 agent（background=true）
    ↓
两方同时完成，返回结果
    ↓
主 agent 综合两方观点：
  - 正方说没问题 + 反方也没找到问题 → 通过
  - 正方说没问题 + 反方找到问题 → 逐条判断：
    - 反方的问题是真实 bug → 标记需修
    - 反方的问题是设计取舍 → 标记可接受
  - 两方都找到问题 → 必须修
    ↓
向用户展示辩论结果：
  - 通过项列表
  - 问题项列表（标注：需修 / 可接受）
  - 建议：执行 / 先修再执行
```

---

## 输出格式

```
═══ 同行评审结果 ═══

正方观点摘要：[1-2 句话]
反方观点摘要：[1-2 句话]

通过项：
  ✓ [项目1] — [正方论据]
  ✓ [项目2] — [正方论据]

问题项：
  ✗ [问题1] — [反方论据] → 判定：需修 / 可接受
  ✗ [问题2] — [反方论据] → 判定：需修 / 可接受

建议：[执行 / 先修 N 个问题再执行 / 重新走方案设计]
```
