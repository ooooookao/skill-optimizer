# LLM-as-a-Judge 评估指南

> 何时读：需要 AI 评估 skill 内容质量时（不只是结构检查）。

---

## 适用场景

结构检查脚本只能检查"有没有"，不能检查"好不好"。以下维度需要 LLM 评估：

| 维度 | 结构检查能做的 | LLM 评估能做的 |
|---|---|---|
| SKILL.md description | 有没有 | 是否准确描述触发条件 |
| step 文件操作指南 | 有没有 checklist | 操作是否清晰可执行 |
| reference 文件 | 是不是速查表 | 内容是否准确、是否遗漏 |
| system_prompt 质量 | 有没有规则 | 规则是否矛盾、是否具体 |
| README 同步度 | 有没有 README | 描述是否与实际项目一致 |
| 子 agent 使用合理性 | 有没有提到子 agent | 逐 step 分析：该 step 是否需要子 agent？需要的话是否用了？ |

---

## 评估 Prompt 模板

### 评估 SKILL.md description

```
请评估以下 skill 的 frontmatter description 是否准确描述了触发条件。

Skill 名称：[name]
Description：[description]

评估维度：
1. 触发条件是否明确？（用户说什么话会触发？）
2. 是否有歧义？（会不会误触发？）
3. 是否覆盖了所有合理场景？

输出格式：
- 触发清晰度：1-5分
- 歧义风险：低/中/高
- 覆盖度：1-5分
- 具体问题：[列表]
- 改进建议：[列表]
```

### 评估 step 文件操作指南

```
请评估以下 step 文件的操作指南是否清晰可执行。

文件名：[filename]
内容：[content]

评估维度：
1. 每步操作是否清晰？（agent 看了知道怎么做吗？）
2. 是否有歧义？（有没有多种理解方式？）
3. 是否有遗漏？（有没有应该但没写的关键步骤？）

输出格式：
- 清晰度：1-5分
- 可执行性：1-5分
- 具体问题：[列表]
- 改进建议：[列表]
```

### 评估 reference 文件

```
请评估以下 reference 文件是否是速查表格式。

文件名：[filename]
内容：[content]

评估维度：
1. 格式是否是速查表？（表格/列表，不是长篇教程）
2. 内容是否准确？
3. 是否有遗漏的关键信息？
4. Token 效率如何？（有没有废话？）

输出格式：
- 格式合规性：是/否
- 内容准确性：1-5分
- Token 效率：1-5分
- 具体问题：[列表]
- 改进建议：[列表]
```

### 评估 README.md 与项目同步度

```
请评估以下 skill 的 README.md 是否与实际项目保持同步。

README 内容：[readme_content]
SKILL.md 内容：[skill_content]
目录结构：[directory_listing]

评估维度：
1. 功能描述是否准确？（README 说的功能 SKILL.md 里有没有？SKILL.md 有的功能 README 有没有提到？）
2. 工作流是否过时？（README 描述的步骤和 step 文件是否一致？）
3. 文件结构是否一致？（README 列的文件树和实际目录是否匹配？）
4. 使用方式是否正确？（示例命令/触发条件是否和 SKILL.md 的触发条件一致？）

输出格式：
- 同步度：1-5分（5=完全同步，3=部分过时，1=严重脱节）
- 过时项：[列表，每项说明哪里不同步]
- 缺失项：[列表，README 应该有但没有的内容]
- 改进建议：[列表]
```

### 评估子 agent 使用合理性

```
请评估以下 skill 的子 agent 使用是否合理。

SKILL.md 内容：[skill_content]
所有 step 文件内容：[step_contents]

逐 step 分析：
对每个 step，判断：
1. 该 step 的核心工作是什么？
2. 这个工作是否需要子 agent？（满足任一即需要）
   - 多个独立任务可并行
   - 单任务输出量大会撑爆主 agent 上下文
   - 需要独立上下文避免污染主流程
3. 如果需要，该 step 是否实际使用了子 agent？

输出格式：
- 每个 step 的评估：[step名] [是否需要子agent] [是否使用了子agent] [合理性:合理/不合理]
- 需要但未使用的 step：[列表]
- 不需要但使用了的 step：[列表]（过度设计）
- 总分：1-4分（4=全部合理，3=1处不合理，2=2处不合理，1=多处不合理）
```
- 改进建议：[列表]
```

### 逐步模拟 Walkthrough（深度评估）

对关键 step 做逐步模拟，比读文件深一层，发现"实际执行才会踩坑"的问题。

```
请对以下 skill 的关键 step 做逐步模拟评估。

SKILL.md 内容：[skill_content]
待评估的 step 文件：[step_content]

模拟场景：[根据 skill 类型构造一个具体场景，如"一个 PyTorch 图像分类项目，目标 dice>=0.9"或"一段 3 万字的武侠小说，用户要求续写 10 章"]

逐步模拟：
对 step 中的每个操作指令，模拟"如果我是 agent，执行这一步：
1. 我知道该做什么吗？（指令是否清晰）
2. 我需要什么信息？这些信息从哪来？（输入是否明确）
3. 我的输出格式是什么？（输出是否明确）
4. 这一步可能出什么错？有降级方案吗？（鲁棒性）
5. 下一步是什么？交接清楚吗？（流程连贯性）"

输出格式：
| 步骤 | 指令清晰度 | 输入明确度 | 输出明确度 | 鲁棒性 | 发现的问题 |
|---|---|---|---|---|---|
| 1. xxx | ✓/✗ | ✓/✗ | ✓/✗ | ✓/✗ | [问题描述] |

总结：
- 该 step 的可执行性评分：1-5分（5=完全可执行，3=有歧义但可推断，1=无法执行）
- 关键问题列表：[需要 agent 自行推断的地方、缺少的信息、可能出错的环节]
```

**选择哪些 step 做 walkthrough：**
- 选最核心的 2-3 个 step（通常是主循环、关键决策点、用户交互点）
- 跳过简单的步骤（如"读取文件"、"创建目录"）
- 优先选有复杂逻辑或多分支的步骤

### 方式 1：主 agent 直接评估

主 agent 读取文件内容，用上述 prompt 模板评估。适用于单个文件的快速评估。

### 方式 2：子 agent 并行评估（未实现）

启动多个子 agent，每个评估一个维度：
- Agent A → 评估 SKILL.md description
- Agent B → 评估 step 文件
- Agent C → 评估 reference 文件

适用于全面评估。

### 方式 3：集成到分析脚本（未实现）

在 `analyze_skill.py` 中添加 LLM 评估维度：
- 结构检查（现有）→ 自动化，快速
- 内容评估（新增）→ 需要 LLM，较慢

建议：先跑结构检查，结构通过后再跑内容评估。

## 评分整合

LLM 评估结果可以整合到总分中：

| 维度 | 权重 | 来源 |
|---|---|---|
| 结构检查 | 60分 | analyze_skill.py 自动 |
| 内容评估 | 40分 | LLM 评估 |

或者作为独立的"内容质量分"展示：

```
总分: 85/100
  结构分: 54/60（自动检查，原始 90/100）
  内容分: 31/40（LLM 评估）
```
