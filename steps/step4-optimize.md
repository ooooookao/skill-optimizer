# Step 4: 执行优化

## 执行清单

- [ ] 4.1 确认优化范围
- [ ] 4.2 运行自动修复脚本（dry-run 模式预览）
- [ ] 4.3 用户确认后执行修复
- [ ] 4.4 展示变更摘要 + 前后对比
- [ ] 4.5 运行质量门禁验证
- [ ] 4.6 记录历史

---

## 详细操作

### 4.1 确认优化范围

根据问题清单，向用户确认要改什么：

```
发现 N 个问题，建议按以下优先级处理：

1. 架构问题（影响最大）
   - [问题1]
   - [问题2]

2. 质量问题
   - [问题3]

3. 内容问题（来自 LLM 评估）
   - [问题4]

你想改哪些？
1. 全部改
2. 只改架构问题
3. 指定具体问题
```

### 4.2 自动修复（dry-run 预览）

```bash
python scripts/fix_skill.py <skill目录路径> --dry-run
```

向用户展示修复计划，确认后再执行。

### 4.3 执行修复

```bash
python scripts/fix_skill.py <skill目录路径>
```

脚本自动修复：
- 创建缺失的目录（steps/references/examples）
- SKILL.md 过长 → 拆分到 reference 文件
- step 文件缺少 checklist → 自动生成
- step 文件缺少 frontmatter → 自动生成

不能自动修复的（内容质量问题），由 agent 手动修改。

### 4.4 展示变更 + 前后对比

```
变更摘要：
| 修改项 | 旧状态 | 新状态 |
|---|---|---|
| SKILL.md | 350行 | 180行 |
| steps/step1.md | 无清单 | 添加5项清单 |
| 新增 | 无 | references/xxx.md |

前后对比：
| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 总分 | 75 | 92 | +17 |
| 结构分 | 55/70 | 65/70 | +10 |
| 内容分 | 20/30 | 27/30 | +7 |
| 严重问题 | 2 | 0 | -2 |
| 高危问题 | 3 | 1 | -2 |
| 门禁 | FAIL | PASS | - |
```

### 4.5 质量门禁验证

```bash
python scripts/quality_gate.py <skill目录路径>
```

不通过时：
- 指出哪些条件还不满足
- 询问用户是否继续修复（回到 4.1）
- 或接受当前状态（交付并告知问题）

### 4.6 记录历史

修复完成后，记录到 `.optimizer_history/`，用于趋势追踪。
