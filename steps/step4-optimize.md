# Step 4: 执行优化

## 执行清单

- [ ] 4.1 确认优化范围
- [ ] 4.2 运行自动修复脚本（dry-run 模式预览）
- [ ] 4.3 用户确认后执行修复
- [ ] 4.4 配置工作区权限（设计新 skill 时）
- [ ] 4.5 展示变更摘要 + 前后对比
- [ ] 4.6 运行质量门禁验证
- [ ] 4.7 记录历史

## 详细操作

### 4.1 确认优化范围

根据问题清单，向用户确认要改什么：

```
发现 N 个问题，建议按以下优先级处理：

1. 架构问题（影响最大）
   - [问题1]
   - [问题2]

2. 质量问题
   - [问题3]

3. 内容问题（来自 LLM 评估）
   - [问题4]

你想改哪些？
1. 全部改
2. 只改架构问题
3. 指定具体问题
```

### 4.2 自动修复（dry-run 预览）

```bash
python scripts/fix_skill.py <skill目录路径> --dry-run
```

向用户展示修复计划，确认后再执行。

### 4.3 执行修复

```bash
python scripts/fix_skill.py <skill目录路径>
```

脚本自动修复：
- 创建缺失的目录（steps/references/examples）
- SKILL.md 过长 → 拆分到 reference 文件
- step 文件缺少 checklist → 自动生成
- step 文件缺少 frontmatter → 自动生成

不能自动修复的（内容质量问题），由 agent 手动修改。

**README 补充（自动+手动）：**
- 缺少 README.md → 自动生成骨架（名称、一句话说明、工作流概览、文件结构、使用示例）
- README 存在但内容过少 → 基于 SKILL.md 补充
- README 描述与项目不同步（LLM 评估同步度 ≤ 3 分）→ 手动更新过时部分

### 4.4 配置工作区权限

**无论设计新 skill 还是优化已有 skill**，只要该 skill 需要调用工具（Bash/Read/Write/Edit 等），就必须包含工作区权限配置流程。

**检查逻辑：**
1. 在 SKILL.md 和 step 文件中搜索 `settings.json`、`permissions`、`工作区权限` 等关键词
2. 如果找到 → 该 skill 已有权限配置，跳过
3. 如果没找到 → 需要补充，执行下方操作

**补充权限配置的操作：**

- **有 Step 0（工作区确认步骤）的 skill** → 在 Step 0 中添加权限配置段落
- **没有 Step 0 的 skill** → 在 SKILL.md 中新增"工作区权限"章节，指向最前面的 step 文件

**在 SKILL.md 或 step 文件中加入以下模式：**

```markdown
## 工作区权限配置

首次运行时，skill 需要确认工作区并配置权限：

1. **确认工作区** — 询问用户目标项目目录（如用户已提供则跳过）
2. **询问是否自动配置权限** — 提示用户：
   > 这个 skill 需要使用 [工具列表] 等工具。要不要我自动把这些工具的权限配好？
   > 配好后后续运行不会反复弹确认框。权限随时可在 settings.json 中收回。
   > - 是，自动配置
   > - 不，逐个确认
3. **如果用户选择"是"** — 读取 `.claude/settings.json`，合并写入 `permissions.allow`。只添加该 skill 实际需要的工具，例如：
   ```json
   {
     "permissions": {
       "allow": [
         "Bash(npm test)",
         "Read(src/**)",
         "Edit(src/**)"
       ]
     }
   }
   ```
   不要无脑全开，按最小权限原则配置。
4. **如果用户选择"否"** — 正常运行，每个工具调用按默认行为逐个确认
```

**注意事项：**
- 只配该 skill 实际会用到的工具，不要无脑全开
- 写入前先读取已有配置，合并而非覆盖
- 告知用户"权限随时可以在 settings.json 里手动收回"
- 对于敏感操作（如 `Bash(rm *)`、`Bash(git push*)`），即使开了全权限也建议 skill 内部二次确认

### 4.5 展示变更 + 前后对比

```
变更摘要：
| 修改项 | 旧状态 | 新状态 |
|---|---|---|
| SKILL.md | 350行 | 180行 |
| steps/step1.md | 无清单 | 添加5项清单 |
| 新增 | 无 | references/xxx.md |

前后对比：
| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| 总分 | 75 | 92 | +17 |
| 结构分 | 55/70 | 65/70 | +10 |
| 内容分 | 20/30 | 27/30 | +7 |
| 严重问题 | 2 | 0 | -2 |
| 高危问题 | 3 | 1 | -2 |
| 门禁 | FAIL | PASS | - |
```

### 4.6 质量门禁验证

```bash
python scripts/quality_gate.py <skill目录路径>
```

不通过时：
- 指出哪些条件还不满足
- 询问用户是否继续修复（回到 4.1）
- 或接受当前状态（交付并告知问题）

### 4.7 记录历史

修复完成后，记录到 `.optimizer_history/`，用于趋势追踪。
