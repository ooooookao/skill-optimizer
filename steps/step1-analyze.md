# Step 1: 分析 + 调研（并行）

**目的**：同时跑架构分析和竞品调研，合并为一份完整报告。
**前置**：用户提供了 skill 目录或名称。
**输出**：问题清单 + 竞品调研报告。

---

## 执行清单

- [ ] 确认 skill 目录路径
- [ ] 并行启动两路：左路分析 + 右路调研
- [ ] 左路：读取目录结构 + SKILL.md + README.md + 运行 analyze_skill.py + LLM 内容评估 + Walkthrough
- [ ] 右路：确认调研范围 + 2 个子 agent 并行调研 + 生成竞品矩阵
- [ ] 合并两路结果为一份报告
- [ ] 进入 Step 2 展示给用户

---

## 详细操作

### 0. 确认 skill 目录

用户可能提供：
- 直接路径（如 `C:\Users\xxx\.claude\skills\my-skill`）
- skill 名称（需在 `.claude/skills/` 下查找）
- 粘贴 SKILL.md 内容（需推断目录）

### 1. 并行启动两路

确认目录后，**同时启动**：

**左路（自动）**：运行分析脚本 + LLM 评估
**右路（子 agent）**：竞品调研

两路互不依赖，可完全并行。

---

### 左路：架构分析

#### 1L. 运行分析脚本

```bash
python scripts/analyze_skill.py <skill目录路径>
```

脚本自动检查 15 项：SKILL.md 行数 / frontmatter / step checklist / step frontmatter / 参考资料格式 / 目录完整性 / README / 跨文件重复 / 工作流导航 / 触发条件 / Gate / 工作区权限 / 经验积累 / 熔断机制 / 用户选择。

#### 2L. LLM 内容评估

主 agent 直接读取文件内容，用 `references/LLM评估指南.md` 中的 prompt 模板评估 5 个维度（满分 40）：
- description 触发条件准确度（10分）
- step 操作指南可执行性（10分）
- reference 内容质量（8分）
- README 与项目同步度（7分）
- 子 agent 使用合理性（5分）——逐 step 分析：该 step 的工作是否需要子 agent？需要的话是否用了？

#### 3L. 逐步模拟 Walkthrough（深度评估）

对最关键的 2-3 个 step 做逐步模拟：构造一个具体场景，模拟 agent 按指令执行，发现"读文件发现不了但实际跑会踩坑"的问题。详见 `references/LLM评估指南.md` 的"逐步模拟 Walkthrough"章节。

walkthrough 发现的问题归入对应维度的扣分（主要是 step 操作指南可执行性）。

#### 4L. 手动补充检查

对照 `references/十一维度检查清单.md` 逐项确认脚本未覆盖的维度。

---

### 右路：竞品调研

#### 1R. 确认调研范围

根据 skill 的功能，确定两个调研方向（直接竞品 + 相邻领域）。

#### 2R. 并行调研

启动 3 个子 agent 并行，各自独立：

**Agent 0 — find-skills 搜索同类 skill**（生态更新最快）：
```
帮我找找有没有 [被评估 skill 的核心功能] 相关的 skill

搜索策略：
1. 先搜精确匹配（如"自动化调参"、"续写小说"、"角色卡生成"）
2. 再搜相关类别（如"代码优化"、"写作辅助"、"AI 工具"）
3. 按下载量/安装量排序，取 top 3

对每个找到的 skill，分析：
- 核心功能（做什么、怎么做的）
- 下载量/活跃度
- 与被评估 skill 的差异（功能覆盖度、设计理念、用户体验）
- 可借鉴的设计思路

即使下载量低，只要设计理念有参考价值就值得分析。
不要因为"没有直接竞品"就只返回一条结论——相关领域的 skill 也有参考意义。
```

记录结果：至少 3 个 skill 的对比分析，含功能差异和可借鉴之处。

**Agent A — 外部竞品调研**

分析 2-3 个相关领域产品：核心功能 / 用户体验 / 社区评价 / 收费模式。

**Agent A prompt 模板**：
```
你是一个 [领域] 领域的资深分析师。请调研："[搜索关键词]"

找出 2-3 个最顶级的产品，分析：
- 核心功能（怎么工作的、检查什么维度）
- 用户体验（操作流程、输出格式）
- 社区评价和用户量
- 收费模式

特别关注：
- 它们怎么发现问题/解决问题？
- 它们的评分/报告系统怎么设计？
- 它们怎么给用户提供可执行的建议？

用中文输出，结构化报告格式，1500字以内。
```

**Agent B — 用户视角问题模拟**

以用户身份模拟 3 个真实使用场景，发现"读文件发现不了但用户实际用会踩坑"的问题。

**Agent B prompt 模板**：
```
你是一个第一次使用这个 skill 的用户。请模拟以下 3 个真实场景：

场景 1：轻量需求 — 用户说"[用户可能说的最简单的一句话]"
场景 2：完整需求 — 用户说"[用户可能说的最完整的一句话]"
场景 3：局部需求 — 用户说"[用户可能说的最具体的一句话]"

对每个场景，分析：
- 用户期望什么？（期望花多少时间、得到什么结果）
- skill 实际会做什么？（走几步、读多少文件、调几个 agent）
- 期望和实际之间的差距在哪？
- 用户可能在哪里失去耐心或困惑？

特别关注：
- 流程是否比用户预期的重？
- 输出是否比用户预期的复杂？
- 有没有用户不关心但 skill 强制执行的步骤？
- 有没有用户期望但 skill 没提供的能力？

用中文输出，结构化报告格式，1000字以内。
```

#### 3R. 生成竞品矩阵 + 用户痛点分析

汇总两个 agent 的结果：
- Agent A → 竞品矩阵，以竞品资深用户身份分析转向条件（痛点→机会 / 底线 / 加分项）
- Agent B → 用户痛点清单，按"期望 vs 实际"的差距排序

#### 4R. 体验优化建议

综合竞品矩阵和用户痛点，从效率（速度+质量）和 UI（交互体验）两个维度提建议。

---

### 合并报告

两路完成后，合并为一份报告展示给用户（进入 Step 2）。报告包含：

```
一、架构分析结果
  - 结构分：XX/60（十一维度自动检查）
  - 内容分：XX/40（LLM 评估 + Walkthrough）
  - 问题清单（按严重程度排序，含失败模式分类）

二、竞品调研结果（完整模式才有）
  - 同类 skill 对比（find-skills 搜索结果）
  - 外部竞品矩阵（Agent A 调研结果）
  - 用户痛点分析（Agent B 用户视角模拟结果）
  - 体验优化建议

三、优化方向（按优先级）
  | 优先级 | 方向 | 理由 | 参考竞品 |
```

### 失败模式分类（仅快速/完整模式）

问题清单中每个问题需标注失败模式（看一眼模式不输出此项）：

| 分类 | 含义 | 典型场景 |
|---|---|---|
| **universal** | 任何模型都会失败 | 缺少 SKILL.md、关键 step 无 checklist、敏感信息泄露 |
| **model-specific** | 小模型更易失败 | 触发条件歧义、复杂工作流无引导、隐式依赖 |
| **regression** | 优化可能引入新问题 | 拆分文件后引用断裂、修改触发条件影响已有使用 |

### ⚠️ 通过条件（Gate）

**完整模式：左右两路都完成后才能进入 Step 2。快速模式：仅左路完成即可。** 自检：

- [ ] 左路完成？（analyze_skill.py 已运行 + LLM 评估已完成 + Walkthrough 已完成）
- [ ] 右路完成？（仅完整模式：find-skills 已分析至少 3 个相关 skill + Agent A 外部竞品调研已返回 + Agent B 用户视角模拟已返回 + 竞品矩阵和用户痛点已生成）
- [ ] 两路结果已合并为一份报告？（快速模式仅包含左路结果）

**任何一项未完成 → 不能进入 Step 2。** 先补完再继续。
