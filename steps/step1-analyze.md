# Step 1: 分析 + 调研（并行）

**目的**：同时跑架构分析和竞品调研，合并为一份完整报告。
**前置**：用户提供了 skill 目录或名称。
**输出**：问题清单 + 竞品调研报告。

---

## 执行清单

- [ ] 确认 skill 目录路径
- [ ] 并行启动两路：左路分析 + 右路调研
- [ ] 左路：读取目录结构 + SKILL.md + README.md + 运行 analyze_skill.py + LLM 内容评估 + Walkthrough
- [ ] 右路：确认调研范围 + 2 个子 agent 并行调研 + 生成竞品矩阵
- [ ] 合并两路结果为一份报告
- [ ] 进入 Step 2 展示给用户

---

## 详细操作

### 0. 确认 skill 目录

用户可能提供：
- 直接路径（如 `C:\Users\xxx\.claude\skills\my-skill`）
- skill 名称（需在 `.claude/skills/` 下查找）
- 粘贴 SKILL.md 内容（需推断目录）

### 1. 并行启动两路

确认目录后，**同时启动**：

**左路（自动）**：运行分析脚本 + LLM 评估
**右路（子 agent）**：竞品调研

两路互不依赖，可完全并行。

---

### 左路：架构分析

#### 1L. 运行分析脚本

```bash
python scripts/analyze_skill.py <skill目录路径>
```

脚本自动检查 15 项：SKILL.md 行数 / frontmatter / step checklist / step frontmatter / 参考资料格式 / 目录完整性 / README / 跨文件重复 / 工作流导航 / 触发条件 / Gate / 工作区权限 / 经验积累 / 熔断机制 / 用户选择。

#### 2L. LLM 内容评估

主 agent 直接读取文件内容，用 `references/LLM评估指南.md` 中的 prompt 模板评估 5 个维度（满分 40）：
- description 触发条件准确度（10分）
- step 操作指南可执行性（10分）
- reference 内容质量（8分）
- README 与项目同步度（7分）
- 子 agent 使用合理性（5分）——逐 step 分析：该 step 的工作是否需要子 agent？需要的话是否用了？

#### 3L. 逐步模拟 Walkthrough（深度评估）

对最关键的 2-3 个 step 做逐步模拟：构造一个具体场景，模拟 agent 按指令执行，发现"读文件发现不了但实际跑会踩坑"的问题。详见 `references/LLM评估指南.md` 的"逐步模拟 Walkthrough"章节。

walkthrough 发现的问题归入对应维度的扣分（主要是 step 操作指南可执行性）。

#### 4L. 手动补充检查

对照 `references/十二维度检查清单.md` 逐项确认脚本未覆盖的维度。

---

### 右路：竞品调研

#### 1R. 确认调研范围

根据 skill 的功能，确定两个调研方向（直接竞品 + 相邻领域）。

#### 2R. 并行调研

启动 3 个子 agent 并行，各自独立：

**Agent 0 — find-skills 搜索同类 skill**（生态更新最快）：
```
帮我找找有没有 [被评估 skill 的核心功能] 相关的 skill

搜索策略：
1. 先搜精确匹配（如"自动化调参"、"续写小说"、"角色卡生成"）
2. 再搜相关类别（如"代码优化"、"写作辅助"、"AI 工具"）
3. 按下载量/安装量排序，取 top 3

对每个找到的 skill，分析：
- 核心功能（做什么、怎么做的）
- 下载量/活跃度
- 与被评估 skill 的差异（功能覆盖度、设计理念、用户体验）
- 可借鉴的设计思路

即使下载量低，只要设计理念有参考价值就值得分析。
不要因为"没有直接竞品"就只返回一条结论——相关领域的 skill 也有参考意义。
```

记录结果：至少 3 个 skill 的对比分析，含功能差异和可借鉴之处。

**Agent A — 外部竞品调研（场景 A）**
**Agent B — 外部竞品调研（场景 B）**

每个 agent 分析 2-3 个产品：核心功能 / 用户体验 / 社区评价 / 收费模式。

**Agent prompt 模板**：
```
你是一个 [领域] 领域的资深分析师。请调研："[搜索关键词]"

找出 2-3 个最顶级的产品，分析：
- 核心功能（怎么工作的、检查什么维度）
- 用户体验（操作流程、输出格式）
- 社区评价和用户量
- 收费模式

特别关注：
- 它们怎么发现问题/解决问题？
- 它们的评分/报告系统怎么设计？
- 它们怎么给用户提供可执行的建议？

用中文输出，结构化报告格式，1500字以内。
```

#### 3R. 生成竞品矩阵 + 迁移分析

汇总两个 agent 的结果，生成竞品矩阵，以竞品资深用户身份分析转向条件（痛点→机会 / 底线 / 加分项）。

#### 4R. 体验优化建议

以被评估 skill 的资深用户身份，从效率（速度+质量）和 UI（交互体验）两个维度提建议。

---

### 合并报告

两路完成后，合并为一份报告展示给用户（进入 Step 2）。报告包含：

```
一、架构分析结果
  - 结构分：XX/60（12维度自动检查）
  - 内容分：XX/40（LLM 评估 + Walkthrough）
  - 问题清单（按严重程度排序）

二、竞品调研结果
  - 同类 skill 对比（find-skills 搜索结果）
  - 外部竞品矩阵
  - 迁移分析
  - 体验优化建议

三、优化方向（按优先级）
  | 优先级 | 方向 | 理由 | 参考竞品 |
```

### ⚠️ 通过条件（Gate）

**左右两路都完成后才能进入 Step 2。** 自检：

- [ ] 左路完成？（analyze_skill.py 已运行 + LLM 评估已完成 + Walkthrough 已完成）
- [ ] 右路完成？（find-skills 已分析至少 3 个相关 skill + 2 个外部竞品 agent 已返回 + 竞品矩阵已生成 + 迁移分析已完成）
- [ ] 两路结果已合并为一份报告？

**任何一项未完成 → 不能进入 Step 2。** 先补完再继续。
