# Step 3: 竞品调研

## 执行清单

- [ ] 确认调研范围（2个场景）
- [ ] 启动 2 个子 agent 并行调研
- [ ] 生成竞品矩阵
- [ ] 展示给用户确认
- [ ] 迁移分析（竞品用户转向条件）
- [ ] 体验优化建议（效率+UI）
- [ ] 整合报告并保存
- [ ] 提出优化方向

---

## 详细操作

### 1. 确认调研范围

根据 skill 的功能，确定两个调研方向：

```
这个 skill 的核心功能是 [XXX]。

需要调研的两个场景：
1. 场景A：[与核心功能直接相关的竞品]
2. 场景B：[相邻领域的竞品/替代方案]

你确认这个方向吗？
```

用户确认后进入下一步。

### 2. 并行调研

启动 2 个子 agent，分别调研不同场景：

**Agent A prompt 模板：**
```
你是一个 [领域] 领域的资深分析师。请调研：
"[搜索关键词]"

找出 2-3 个最顶级的产品，分析：
- 核心功能（怎么工作的、检查什么维度）
- 用户体验（操作流程、输出格式）
- 社区评价和用户量
- 收费模式

特别关注：
- 它们怎么发现问题/解决问题？
- 它们的评分/报告系统怎么设计？
- 它们怎么给用户提供可执行的建议？

用中文输出，结构化报告格式，1500字以内。
```

**Agent B prompt 模板：** 同上，替换领域和关键词。

### 3. 生成竞品矩阵

汇总两个 agent 的调研结果：

```
| 产品 | 定位 | 核心优势 | 核心短板 | 适合人群 |
|---|---|---|---|---|
| 产品A | ... | ... | ... | ... |
| 产品B | ... | ... | ... | ... |
| 产品C | ... | ... | ... | ... |
```

### 4. 展示给用户确认

向用户展示竞品矩阵，确认：
- 竞品选择是否合理？
- 分析是否准确？
- 有没有遗漏的重要竞品？

用户确认后进入下一步。

### 5. 迁移分析

以竞品资深用户的身份，分析转向条件：

```
我是 [竞品A] 的资深用户，转向条件：

竞品A 的痛点：
- 痛点1 → 我们的机会1
- 痛点2 → 我们的机会2

必须满足：
- 条件1（底线）
- 条件2（底线）

加分项：
- 条件3（差异化优势）
```

对每个主要竞品都做迁移分析。

### 6. 体验优化建议

以自己产品的资深用户身份，从两个维度提建议：

**效率（速度 + 工作质量）：**
- 功能1：[描述] — 解决什么问题
- 功能2：[描述] — 解决什么问题

**UI（交互体验）：**
- 功能1：[描述] — 解决什么问题
- 功能2：[描述] — 解决什么问题

### 7. 整合报告并保存

将所有分析整合为一份报告，保存到 skill 目录：

```
[skill目录]/research_report.md
```

报告结构：
```
# 竞品调研报告

## 竞品矩阵
## 迁移分析
## 体验优化建议
## 优化方向（按优先级）
```

### 8. 提出优化方向

```
| 优先级 | 优化方向 | 理由 | 参考竞品 |
|---|---|---|---|
| P0 | [功能1] | 竞品A的用户最需要 | 竞品A |
| P1 | [功能2] | 市场空白 | 竞品B |
| P2 | [功能3] | 差异化优势 | 无 |
```

用户确认后，进入 step4 执行优化。
